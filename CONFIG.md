# Configuration Reference

This file is the authoritative reference for every field in the active config (currently `configs/pilot.yaml`, compiled to `config.json` at build time).

## Authoring model

- **Source of truth**: `configs/<ACTIVE_CONFIG>.yaml`, where `ACTIVE_CONFIG` is set in `.env`.
- **Runtime artifact**: `config.json` — generated by `npm run build-config`. Never hand-edit; changes will be overwritten by the next build.
- **Switching configs**: edit `.env` to point at a different YAML in `configs/`, run `npm run build-config`. For deployment, `./deploy.sh` runs the build automatically before `gcloud run deploy`, so `.env` is canonical for both local and prod.

To create a new config, copy `configs/pilot.yaml` to a new filename and edit values. **Convention**: set the new YAML's `experiment_config` field to its own filename (e.g. `"configs/experiment_a.yaml"`) so MongoDB `experiment_id` logs identify which config a participant ran. The pilot YAML preserves its original `"configs/timeline.json"` label verbatim to maintain log continuity with existing pilot data — do not change it.

## Field reference

### `experiment_config`
- **Type**: string (path-like label)
- **Pilot value**: `"configs/timeline.json"`
- **Read by**: Node (`server.js:25`), Browser (`main.js:202` via `/api/config`)
- **Effect**: `server.js:27` extracts the basename (`split('/').pop()`) and stores it in MongoDB logs as `experiment_id`. The string does not need to point at an actual file — it's a label only.
- **Convention for new configs**: set to the YAML's own filename (`"configs/<this-file>.yaml"`).

### `bandit_assignment_mode`
- **Type**: string enum
- **Accepted values**: `"session_fixed"` | `"round_changing"` (`models.py:128,133`)
- **Pilot value**: `"round_changing"`
- **Read by**: Python (`models.py:610,657`)
- **Effect**: `"session_fixed"` keeps one zone for all rounds in a session; `"round_changing"` assigns a fresh zone each round.
- **Default if absent**: `"session_fixed"` (`models.py:610`)

### `textbox_feedback`
- **Type**: bool
- **Pilot value**: `true`
- **Read by**: Python (`models.py:611`, branch at `models.py:101`)
- **Effect**: when `true`, inserts a `stage_type: "feedback"` text-input stage after each choice stage; responses are written to MongoDB.
- **Default if absent**: `false`

### `session_demonstrators`
- **Type**: string enum
- **Accepted values**: `"all"` | `"different"`. Any other value raises `ValueError` (`models.py:55`).
- **Pilot value**: `"different"`
- **Read by**: Python (`models.py:612`, branches at `models.py:46,51`)
- **Effect**: `"all"` generates all 4 expert/novice combos per round-set (EE/EN/NE/NN); `"different"` keeps only mixed pairs (EN, NE).
- **Default if absent**: `"all"`

### `prop_of_sessions`
- **Type**: float
- **Accepted range**: `(0, ∞)`. Values `≥1.0` keep all sessions; values `<1.0` keep `max(1, floor(N * prop))` sessions.
- **Pilot value**: `1`
- **Read by**: Python (`models.py:613`, branch at `models.py:120`)
- **Effect**: subsamples generated sessions to that proportion. Use `1` to keep everything.
- **Default if absent**: `0.5`

### `omit_explicit_experience_transfer_message`
- **Type**: bool
- **Pilot value**: `true`
- **Read by**: Python (`models.py:614`, branches at `models.py:445,510`)
- **Effect**: when `true`, suppresses the secondary overlay text "Some starships have experience in every zone…" in intro and watch transitions. Affects on-screen text only.
- **Default if absent**: `false`

### `name_demonstrators`
- **Type**: bool
- **Pilot value**: `true`
- **Read by**: Python (`models.py:615`, branches at `models.py:258,350,425,477`)
- **Effect**: when `true`, assigns one of 36 starship names (Falcon, Phoenix, Orion, …) to each demonstrator and includes `demonstrator_name` in the timeline JSON; the client displays them.
- **Default if absent**: `false`

### `present_demonstrators_apriori`
- **Type**: bool
- **Pilot value**: `true`
- **Read by**: Python (`models.py:616`, branches at `models.py:331,385`)
- **Effect**: when `true`, prepends a `stage_type: "demonstrator_presentation"` meta stage to each session showing both demonstrators' style/color before gameplay starts. Also adjusts the intro overlay to omit the "new session" line when the presentation already covered it.
- **Default if absent**: `false`

### `display_running_total_reward`
- **Type**: bool
- **Pilot value**: `true`
- **Read by**: Node (`server.js:74`, surfaced via `/api/config`), Browser (`main.js:203,4651`)
- **Effect**: when `true`, displays "TOTAL REWARD: N" text above the reward tank during play stages (cosmetic; does not affect game mechanics or logging).
- **Default if absent**: `false`

### `verbose`
- **Type**: bool
- **Pilot value**: `false`
- **Read by**: Node (`server.js:76`), Browser (`main.js:86` via `verboseLog()`)
- **Effect**: when `true`, gates extra `console.log()` output in the browser (demonstrator config, Thompson sampler trajectories, bandit payoffs). Does not affect timeline generation or MongoDB logging.
- **Default if absent**: `false`

### `demonstrator_config` (object)

Trajectory generation config for the demonstrators shown in watch stages. Travels Node → Python via argv as a JSON-stringified blob (`server.js:196` → `models.py:641`), so the on-disk YAML format does not affect the IPC path.

#### `demonstrator_config.source`
- **Type**: string enum
- **Accepted values**: `"inline"` | `"file"` (`models.py:22,176,210,411`)
- **Pilot value**: `"inline"`
- **Read by**: Python (`models.py`), Browser (`main.js:204`)
- **Effect**: `"inline"` generates trajectories in JS at watch time using `bandit_payoffs` and the Thompson sampler in `main.js`; `"file"` loads pre-computed trajectories from `timeline_models/bandits_data.json` (~6MB).

#### `demonstrator_config.bandit_payoffs`
- **Type**: array of floats in `[0, 1]`. Required when `source: "inline"` — `models.py:27` raises `ValueError` if missing.
- **Pilot value**: `[0.0, 0.1, 0.2, 0.3, 0.35, 0.4, 0.45, 0.5, 0.55, 0.6, 0.75, 0.8]`
- **Read by**: Python (`models.py:26,182`), Browser (`main.js:2214`)
- **Effect**: per-arm reward probabilities. Permuted per zone, then passed to the Thompson sampler. Length should match the asteroid-cell count (12 in the pilot).

#### `demonstrator_config.expert_demonstrator_experience`
- **Type**: int ≥ 0
- **Pilot value**: `128`
- **Read by**: Browser (`main.js:2220,2493,2565,2835,3917,4169`)
- **Effect**: number of invisible warmup iterations the expert demonstrator's Thompson sampler runs before the visible trajectory. Higher = more "learned" expert; the visible run starts from the warmed-up posterior.

#### `demonstrator_config.novice_demonstrator_experience`
- **Type**: int ≥ 0
- **Pilot value**: `0`
- **Read by**: Browser (same lines as expert)
- **Effect**: warmup iterations for novice demonstrators. Typically `0` so novice behavior reflects raw exploration with `α=β=1` priors.

#### `demonstrator_config.demonstrator_sampling_strategy`
- **Type**: string
- **Pilot value**: `"thompson"`
- **Read by**: Browser (`main.js:2495,2837,4171`) — written to MongoDB log only.
- **Effect**: **informational / log-only**. The actual sampling strategy is hardcoded to Thompson regardless of this value. Field exists so post-hoc analyses can record which strategy was active.

## Pilot baseline

These are the exact values used by the initial pilot study. `config.pilot.json` (committed) is a frozen snapshot — restore from it if `configs/pilot.yaml` is ever accidentally modified.

```yaml
experiment_config: configs/timeline.json
omit_explicit_experience_transfer_message: true
bandit_assignment_mode: round_changing
textbox_feedback: true
session_demonstrators: different
prop_of_sessions: 1
name_demonstrators: true
present_demonstrators_apriori: true
display_running_total_reward: true
verbose: false
demonstrator_config:
  source: inline
  bandit_payoffs: [0.0, 0.1, 0.2, 0.3, 0.35, 0.4, 0.45, 0.5, 0.55, 0.6, 0.75, 0.8]
  expert_demonstrator_experience: 128
  novice_demonstrator_experience: 0
  demonstrator_sampling_strategy: thompson
```

## Verification

Each field's described effect was verified against the code (read-sites, branches, defaults). Fields that are **runtime-visible** in the browser (`bandit_assignment_mode`, `textbox_feedback`, `session_demonstrators`, `prop_of_sessions`, `omit_explicit_experience_transfer_message`, `name_demonstrators`, `present_demonstrators_apriori`, `display_running_total_reward`, `verbose`, `demonstrator_config.source`, `expert/novice_demonstrator_experience`) should also be sanity-checked end-to-end via manual playthrough when the config is changed. See the project plan for the playthrough protocol — always restore `config.json` from `config.pilot.json` after toggling.

Two fields are **log-only** and require no playthrough:
- `experiment_config` — only its basename is read (for the MongoDB `experiment_id` field).
- `demonstrator_config.demonstrator_sampling_strategy` — written to logs but never branched on.

`bandit_payoffs` is verified by code trace; verifying actual reward probabilities requires statistical analysis of trajectory logs rather than playthrough.
