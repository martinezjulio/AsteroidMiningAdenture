# Configuration Reference

This file is the authoritative reference for every field in the active config (currently `configs/pilot_D_2026-01-20.yaml`, compiled to `config.json` at build time).

## Authoring model

- **Source of truth**: `configs/<ACTIVE_CONFIG>.yaml`, where `ACTIVE_CONFIG` is set in `.env`.
- **Runtime artifact**: `config.json` — generated by `npm run build-config`. Never hand-edit; changes will be overwritten by the next build.
- **Switching configs**: edit `.env` to point at a different YAML in `configs/`, then `npm run build-config`. For deployment, `./deploy.sh` runs the build automatically before `gcloud run deploy`, so `.env` is canonical for both local and prod.

To create a new config, copy `configs/pilot_D_2026-01-20.yaml` to a new filename and edit values. **Convention**: set the new YAML's `experiment_config` field to its own filename so MongoDB `experiment_id` logs identify which config a participant ran.

## Token grammar

`round_game_sequence_conditions` and `session_end_stages` accept these stage tokens:

| Token | Renders as | Notes |
|---|---|---|
| `play` | a play stage | participant mines for `num_pulls_per_play_game` pulls |
| `watch-demo-1` | a watch stage | demo with `demo_1_prior_experience` warmup; `num_pulls_per_watch_game` pulls |
| `watch-demo-2` | a watch stage | demo with `demo_2_prior_experience` warmup |
| `choice` | a choice stage | participant picks between demo-1 / demo-2; transfers to a new zone |
| `online-choice` | an online-choice stage | log-only variant of choice |
| `blind` / `indicate` | specialty stages | currently parallel to watch — reserved for future protocols |
| `feedback` | a free-text feedback stage | logged to MongoDB |

Unknown tokens cause Python to raise `ValueError` at timeline-generation time.

## Field reference

### `experiment_config`
- **Type**: string (path-like label)
- **Read by**: Node (`server.js:25`), Browser (`main.js:202` via `/api/config`)
- **Effect**: only the basename is stored in MongoDB as `experiment_id`. The string need not point at a real file.
- **Convention**: set to the YAML's own filename for new configs.

### `round_game_sequence_conditions`
- **Type**: list of lists of stage tokens
- **Required**.
- **Read by**: Python (`models.py`)
- **Effect**: each inner list is one ROUND. The chosen condition for a session is repeated `num_rounds` times. Sessions are produced from this list via `sampling_method`.

### `session_end_stages`
- **Type**: list of stage tokens (may be empty)
- **Required** (use `[]` to skip).
- **Effect**: appended ONCE per session, after the `num_rounds` repetitions of the round-sequence. The pilot uses `[choice, feedback]` here; putting these in the round-sequence instead would repeat them every round.
- **Zone behavior**: a `choice`-like end stage advances to a new zone (transfer); other end stages share that zone.
- **All-play sessions**: if a session's round-sequence contains no `watch-demo-*` token, demo-dependent end stages (`choice`, `online-choice`, `feedback`, plus the other choice-likes `blind`/`indicate`) are dropped from that session's end-stage list, and the per-session `demonstrator_presentation` prepend (controlled by `present_demonstrators_apriori`) is skipped. This lets a config mix all-play conditions with watch+play conditions in `round_game_sequence_conditions` without authoring per-session overrides.

### `num_rounds`
- **Type**: int ≥ 1
- **Required**.
- **Effect**: per-session repetition count of the chosen round-sequence.

### `num_pulls_per_play_game`
- **Type**: int ≥ 1
- **Required**.
- **Effect**: number of asteroid pulls per `play` stage instance.

### `num_pulls_per_watch_game`
- **Type**: int ≥ 1
- **Required**.
- **Effect**: number of asteroid pulls per `watch-demo-*` stage instance.

### `sampling_method`
- **Type**: string enum
- **Accepted values**:
  - `"all_conditions_shuffled"` — use each condition once per pass, in shuffled order.
  - `"conditions_sampled_uniformly"` — draw `num_sessions` conditions uniformly at random with replacement.
- **Required**.
- **Effect**: controls how `round_game_sequence_conditions` becomes the timeline's session list.

### `num_sessions`
- **Type**: int ≥ 1, or `null`
- **Required iff** `sampling_method == "conditions_sampled_uniformly"`. Ignored otherwise.
- **Effect**: number of conditions to draw per outer pass.

### `num_times_conditions_repeat`
- **Type**: int ≥ 1
- **Default**: `1`.
- **Effect**: outer multiplier — runs the `sampling_method` this many times. Total sessions = (sessions-per-pass) × `num_times_conditions_repeat`.

### `prop_of_sessions`
- **Type**: float in `(0, ∞)`
- **Default**: `1.0`.
- **Effect**: subsamples sessions AFTER the sampling method has produced them. `< 1.0` keeps `max(1, floor(N × prop))` sessions; `≥ 1.0` keeps all.

### `demo_1_prior_experience` / `demo_2_prior_experience`
- **Type**: int ≥ 0
- **Required**.
- **Read by**: Browser (`main.js`, via `/api/config`'s `demonstrator_config`)
- **Effect**: Thompson sampler warmup iterations run from `α=β=1` priors before each visible watch trajectory begins. Higher = more "experienced" demonstrator. `0` reproduces raw exploration.

### `bandit_payoffs`
- **Type**: array of floats in `[0, 1]`
- **Required**, non-empty.
- **Read by**: Python (`models.py`), Browser (via `/api/config`)
- **Effect**: per-arm reward probabilities. Permuted per zone. Length must match the asteroid-cell count (12 in the pilot).

### `demonstrator_sampling_strategy`
- **Type**: string
- **Default**: `"thompson"`.
- **Effect**: **informational / log-only**. Behavior is hardcoded to Thompson sampling regardless of value. Logged to MongoDB so analyses can record which strategy was active.

### `bandit_assignment_mode`
- **Type**: string enum
- **Accepted values**: `"session_fixed"` | `"round_changing"`
- **Required**.
- **Effect**: `"session_fixed"` keeps one zone for all rounds in a session; `"round_changing"` assigns a fresh zone each round.

### `experience_message_text`
- **Type**: string or `null`
- **Default**: `null`.
- **Effect**: optional secondary overlay text shown on watch stages. `null`/`""` omits it. Replaces the old hardcoded experience-claim and the deprecated `omit_explicit_experience_transfer_message` flag.

### `name_demonstrators`
- **Type**: bool
- **Default**: `false`.
- **Effect**: when `true`, demonstrators are assigned starship names rendered in the UI.

### `present_demonstrators_apriori`
- **Type**: bool
- **Default**: `false`.
- **Effect**: when `true`, prepends a `demonstrator_presentation` meta stage to each session.

### `display_running_total_reward`
- **Type**: bool
- **Default**: `false`.
- **Read by**: Node (`server.js`), Browser
- **Effect**: when `true`, shows the running total reward beneath the icon row from the first `demonstrator_presentation` of each session. Stays visible for the rest of the session and is reported on the end-of-game screen before the Prolific return button.

### `total_reward_scope`
- **Type**: string — `'per_session'` or `'across_sessions'`.
- **Default**: `'per_session'`.
- **Read by**: Node (`server.js`), Browser, Python (`models.py`).
- **Effect**: controls how the running total aggregates and is presented when `display_running_total_reward: true`.
  - `'per_session'`: tally resets at the start of each session. The in-game display labels each session's tally (`Session 1 — Total Reward: X`); once a session ends its tally freezes and the next session's live tally appears beside/below it. The end-of-game screen lists every session's tally plus a `Combined Total`.
  - `'across_sessions'`: a single running total that never resets. The in-game display shows just `TOTAL REWARD: N`. Python emits a different `demonstrator_presentation` message at the start of session 2+ ("Your TOTAL REWARD continues from your previous score…") so the on-screen wording matches the actual carryover.
- Ignored when `display_running_total_reward: false`.

### `report_play_rewards_between_rounds`
- **Type**: bool
- **Default**: `false`.
- **Read by**: Python (`models.py`), Browser.
- **Effect**: when `true`, Python injects a `round_recap` meta stage between rounds inside a session (i.e. after every round except the last). The browser's `setupRoundRecap` sums the play-game rewards of every round so far in the session and names each round by its **zone** (participants never see the word "round") — e.g. after the second of three rounds: *"ZONE 4 COMPLETE — Good job! You earned 8 rewards in zone 3 and 6 rewards in zone 4. Can you beat that in zone 5?"*, button "Continue to next zone". Under `session_fixed` (same zone every round) it reads *"ZONE 3 · KEEP GOING — You've earned 14 rewards in zone 3 so far. Can you keep it up?"*. Recap is skipped for any round that had zero play games.

### `reward_breakdown_display`
- **Type**: string — `'none'` or `'per_game'`.
- **Default**: `'none'`.
- **Read by**: Node (`server.js`), Browser.
- **Effect**: with `display_running_total_reward: true`, `'per_game'` replaces the single `TOTAL REWARD: N` line with a **reward ledger**: one row per expedition (session), one box per play or watch game, and the total underneath. A play box is a mini Reward Tank (outlined in the game's zone color, one slot per shot, filled green per reward earned). A watch box is a same-size placeholder showing the watched partner's name (`"WATCH"` when `name_demonstrators` is false), so every expedition has the same number of boxes in the same columns; the boxes only line up exactly when `num_pulls_per_watch_game` equals `num_pulls_per_play_game`. `online-choice` stages get no box. A box appears when its game starts; only the current game's box is bright and every other box is dimmed, while the `EXPEDITION n` caption dims only once that expedition is over. Future expeditions are not shown until they begin. The end-of-game screen draws the same ledger with zone labels and nothing dimmed. **Design note**: the ledger keeps per-game, per-zone reward information visible across expeditions (the summary bar's per-game "+N" clears each session) and reveals the number of play games in the current expedition — leave it `'none'` for conditions where that should not be shown.
- Participant-facing copy calls a session an **expedition** (transition slides, ledger captions, end screen); config/logs/timeline JSON keep `session`.
- **Zone numbering**: played zones are numbered consecutively in play order across sessions (zone 0 = practice). End-of-session `choice`/`feedback` stages carry a virtual zone `1000 + session_index` (own border color, never played) so they don't create gaps; their log rows have `zone_global_index` ≥ 1001.

### `prolific_completion_url`
- **Type**: string (URL) or omitted.
- **Default**: none — the browser falls back to a hard-coded completion URL in `showEndOfGameMessage` (main.js).
- **Read by**: Node (`server.js`), Browser.
- **Effect**: where the "Return to Prolific" button on the final screen sends the participant. Put the study's completion code here (`https://app.prolific.com/submissions/complete?cc=XXXXXXXX`) so a new study only needs a YAML change.

### `bonus_per_reward` / `bonus_currency`
- **Type**: number (money per reward point) / string (currency prefix).
- **Default**: no bonus line / `$`.
- **Read by**: Node (`server.js`), Browser.
- **Effect**: the final screen shows `BONUS $0.82` and `41 rewards × $0.02 each` under the total, computed as TOTAL REWARD × `bonus_per_reward`. While playing, a small blue `Bonus $0.82` line sits under the running total (either display mode). Omit `bonus_per_reward` to hide both. Display only — it does not affect what Prolific pays; keep it in sync with the study's bonus rule.

### `verbose`
- **Type**: bool
- **Default**: `false`.
- **Effect**: when `true`, gates extra `console.log()` output in the browser. Does not affect timeline generation or MongoDB logging.

## Pilot D baseline

These are the values used by `configs/pilot_D_2026-01-20.yaml` — designed to reproduce the original pilot's dynamics under the new schema.

```yaml
experiment_config: configs/pilot_D_2026-01-20.yaml
round_game_sequence_conditions:
  - [watch-demo-1, play, watch-demo-2, play]
  - [watch-demo-2, play, watch-demo-1, play]
session_end_stages: [choice, feedback]
num_rounds: 3
num_pulls_per_play_game: 6
num_pulls_per_watch_game: 6
sampling_method: all_conditions_shuffled
num_sessions: null
num_times_conditions_repeat: 1
prop_of_sessions: 1
demo_1_prior_experience: 128
demo_2_prior_experience: 0
bandit_payoffs: [0.0, 0.1, 0.2, 0.3, 0.35, 0.4, 0.45, 0.5, 0.55, 0.6, 0.75, 0.8]
demonstrator_sampling_strategy: thompson
bandit_assignment_mode: round_changing
experience_message_text: null
name_demonstrators: true
present_demonstrators_apriori: true
display_running_total_reward: true
total_reward_scope: per_session
report_play_rewards_between_rounds: false
verbose: false
```

This produces:
- 2 sessions per participant, each running one of the two round-sequences (3 rounds × `[watch-demo-X, play, watch-demo-Y, play]`), then `choice + feedback`.
- demo-1 has 128 Thompson warmup iterations (≡ pilot's "expert"); demo-2 has 0 (≡ "novice").
- New zone per round (`round_changing`); choice stage gets a new zone (transfer).

## Migration notes (vs old pilot.yaml schema)

| Old field | New field / replacement |
|---|---|
| `expert_demonstrator_experience` | `demo_1_prior_experience` (top-level) |
| `novice_demonstrator_experience` | `demo_2_prior_experience` (top-level) |
| `omit_explicit_experience_transfer_message` | `experience_message_text` (`null` ≡ omitted) |
| `session_demonstrators: "all"\|"different"` | dropped — encode pairings explicitly in `round_game_sequence_conditions` |
| `textbox_feedback: bool` | dropped — put `feedback` token in `session_end_stages` |
| `demonstrator_config.source: "inline"\|"file"` | dropped — file-mode removed; always inline |
| `demonstrator_config` (object wrapper) | flattened — children promoted to top level |
